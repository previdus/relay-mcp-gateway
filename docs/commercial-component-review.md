# Ten commercial offerings — component review checkpoint

Reviewed 17 October 2026 from selected primary-source sections. This is a curated set of commercial gateway offerings, not a market-share ranking. No vendor runtime, paid tier or performance claim was independently tested. A vendor's support statement applies to the named page, version and edition, not automatically its entire product family. The earlier broader comparison remains in [gateway-landscape.md](gateway-landscape.md).

| Offering and primary reference | Relevant documented capability / limit | Decision for Relay |
|---|---|---|
| [Gravitee](https://www.gravitee.io/blog/mcp-gateway) | Unified MCP/LLM/A2A governance, identity integration, fine-grained authorization, delegation and observability. Its article's general session/state claims need protocol-version qualification. | Bind verified subject and client identity independently of execution credentials. Keep MCP version behavior grounded in the actual specification. Interactive consent remains a gap. |
| [KrakenD Enterprise](https://www.krakend.io/docs/enterprise/ai-gateway/mcp-gateway/) | HTTP no-op proxy configuration, auth/traffic/telemetry middleware and GET/POST/DELETE paths. This gateway page explicitly excludes stdio; server-conversion features are a separate surface. | Keep transparent proxying distinct from our protocol mediation and configured stdio support. Add per-upstream connection/operation limits. |
| [Kong AI MCP Proxy](https://developer.konghq.com/plugins/ai-mcp-proxy/) | Per-tool ACLs apply to discovery and invocation; deny entries precede allows. The reviewed plugin page names supported MCP revisions and excludes several conversion/advanced modes. | Add explicit argument forbids overriding allows. Do not infer that all Kong gateway protocols are native MCP backend transports. |
| [Traefik Hub](https://doc.traefik.io/traefik-hub/mcp-gateway/mcp) | OAuth metadata, policy evaluation, list filtering and output-sensitive controls. List policies lack call arguments; header-based routing needs its documented body-consistency caveat. | Preserve authenticated discovery and call-time parameter enforcement. Result inspectors remain tool-only; prompt/resource inspection is a real gap. |
| [AWS AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-core-concepts.html) | Managed MCP, HTTP and inference target categories; OAuth/JWT and AWS identity options, target credential providers and API/Lambda conversion. | Keep inbound identity and upstream credentials separate. SigV4 and cloud workload credential providers are not implemented here. |
| [Azure API Management](https://learn.microsoft.com/en-us/azure/api-management/secure-mcp-servers) | Subscription keys, Entra token validation and credential-manager policies for outbound access. Some linked setup paths are experimental. | Reuse external identity providers; do not add an ad hoc login/token issuer. Managed identity and credential-manager parity remain gaps. |
| [Apigee](https://docs.cloud.google.com/apigee/docs/api-platform/apigee-mcp/apigee-mcp-overview) | API-to-tool exposure, discovery, governance and tool metrics. The page specifies tool/capacity/OpenAPI restrictions and an SSE limitation for the described endpoint. | Keep native MCP transport support distinct from API conversion. No generic REST/OpenAPI conversion or managed portal claimed. |
| [Tyk MCP Gateway](https://tyk.io/tyk-mcp-gateway/) | Documents remote MCP, per-consumer/tool controls, filtered discovery, common identity mechanisms and Kubernetes/GitOps management. Marketing exclusivity assertions are not independent evidence. | Retain per-tool quotas and fresh access filtering. Do not copy its exclusivity language or claim equivalent identity/GitOps breadth. |
| [Solo Enterprise for agentgateway](https://docs.solo.io/agentgateway/standalone/latest/documentation/configuration/security/backend-authn/) | Explicit backend credential choices include static, cloud identity, signed JWT, OAuth exchange and cross-app trust. Standalone/Kubernetes field names and availability differ. | Preserve a credential-provider extension point. Add no permissive fallback or arbitrary credential passthrough; workload identity/cross-app exchange remain staged. |
| [Portkey / PRISMA AIRS](https://portkey.ai/blog/introducing-the-mcp-gateway/) | Centralizes upstream authentication, permissions, policy and correlated model/tool visibility. The introduction describes parameter capture; implementation details and current edition need further documentation. | Keep metadata-only audit rather than default tool payload capture. Cross-LLM correlation is not a full agent trace product here. |

## Decisions from this pass

Implemented: bounded opaque-token introspection; optional access-token type/age and OAuth client binding; strict bearer extraction and proof-bound-token rejection; bounded relationship-service responses; explicit OpenFGA namespace migration; deny-overrides argument policies; trusted tenant/role routing selectors and deterministic priority selection; upstream connection/total time budgets; UI controls for these identity, route and deadline settings.

Not implemented: interactive OAuth consent/PKCE client lifecycle, DPoP/mTLS proof verification, SigV4/SPIFFE/cloud workload attestation, arbitrary IAM providers in one listener, generalized external-policy plugins with sandboxing, backend resource ownership, health-aware global routing, effect-safe automatic retries, API conversion, and full agent execution tracing. These are candidates for later research/implementation cycles, not claimed parity.
