# Component research checkpoint — 17 October 2026

The requested programme is **not complete**. This checkpoint records targeted body-section inspection of 40 papers (10 per area), six standards, one OpenFGA reference and two reliability articles. It is not a claim that every page/proof/appendix was read, or that model/system benchmarks were reproduced. The 200-article target remains at **2/200**; standards, documentation and vendor pages are not relabeled as articles to inflate that count. Ten commercial offerings were separately reviewed from selected primary-source sections. They are a curated comparison, not an independently ranked worldwide top ten.

The ten-cycle research/implementation/review programme for each area remains pending beyond this first hardening pass. The plan lists the intended questions; a list of ten checklist items is not counted as ten completed cycles.

All paper bodies were retrieved before annotation. Requested arXiv versions and actual redirect URLs/hashes are retained; front-page titles sometimes differ from later metadata. OAuthShield/Cerberus and the ReBAC mining title are explicitly distinguished. The original rendezvous technical report could not be fetched with a verified certificate chain, so Jump Consistent Hash replaced it; certificate verification was not disabled. Corrected FAPI/SSO/Chubby links and an explicit PDF replaced failed/thin HTML fetches. No unavailable/abstract-only source is counted as a reviewed paper.

## Authentication

| Primary paper | Finding and limit | Engineering decision |
|---|---|---|
| [A Comprehensive Formal Security Analysis of OAuth 2.0](https://arxiv.org/html/1601.01229v1) | OAuth flow analysis separates authorization, authentication and session integrity; fixes depend on the modeled flow and attacker. | Keep the gateway a resource server; do not turn arbitrary OAuth tokens into login evidence or implement an embedded identity provider. |
| [The Web SSO Standard OpenID Connect](https://arxiv.org/html/1704.08539v1) | OIDC adds identity semantics and discovery/registration attack surfaces beyond OAuth. Its proof does not certify every implementation. | Pin issuer/JWKS and use local subject bindings; require access-token type when the issuer supports that profile. |
| [An Extensive Formal Security Analysis of the OpenID Financial-grade API](https://arxiv.org/html/1901.11520v1) | FAPI strengthens high-risk flows with token binding and explicit attacker assumptions. Its configurations are not interchangeable. | Reject cnf-bound tokens on the bearer path until the corresponding proof verifier exists. |
| [On the security of modern Single Sign-On Protocols: Second-Order Vulnerabilities in OpenID Connect](https://arxiv.org/html/1508.04324v1) | Malicious discovery endpoints can expose credentials in later protocol steps. The original-version title differs from later metadata. | Validate deployment-owned security URLs and disallow redirects; do not discover endpoints from unverified token fields. |
| [SPRESSO: A Secure, Privacy-Respecting Single Sign-On System for the Web](https://arxiv.org/html/1508.01719v1) | SPRESSO addresses identity-provider privacy through a separate SSO protocol and formal model. It is not a drop-in MCP verifier. | Avoid unnecessary token/payload retention; defer new SSO protocols to identity providers. |
| [Cerberus: Query-driven Scalable Vulnerability Detection in OAuth Service Provider Implementations](https://arxiv.org/html/2110.01005v1) | The fetched original version is titled OAuthShield. Its static analyzer checks OAuth server implementation logic; later metadata calls it Cerberus. | Use adversarial verification tests; do not claim that using a library proves correct integration or that we ran this analyzer. |
| [A Gateway Architecture for Enterprise MCP Authentication](https://arxiv.org/html/2608.10760v1) | The experience paper separates user/non-user personas and execution credentials, with explicit service-account authorization. It also describes older password-grant patterns. | Add optional verified client_id binding; retain separate upstream credentials. Reject copying password grants merely because a paper deploys them. |
| [Zero-Trust Authorization and Discovery for Enterprise MCP](https://arxiv.org/html/2609.22573v1) | The enterprise MCP paper proposes heterogeneous credential adapters and pre-auth discovery; its SDK comparisons are version specific. | Implement bounded RFC 7662 introspection, but retain authenticated catalog discovery rather than expose private schemas publicly. |
| [Formal Security Analysis of the OpenID FAPI 2.0](https://publ.sec.uni-stuttgart.de/hosseynikuesterswuertele-iacr-2024-078.pdf) | FAPI 2.0 analysis finds interactions among PAR, DPoP, mTLS and issuer binding; security follows revised specifications and the model. | Treat proof-of-possession as a separate complete contract, not a certificate/proxy-header checkbox. |
| [O Single Sign-Off, Where Art Thou?](https://www.usenix.org/system/files/conference/usenixsecurity18/sec18-ghasemisharif_0.pdf) | The empirical SSO study finds account/session access can outlive user remediation; observations cover its tested services and era. | No positive introspection cache in this release; require fresh checks and document JWT revocation limits. |

## Authorization

| Primary paper | Finding and limit | Engineering decision |
|---|---|---|
| [Zanzibar](https://www.usenix.org/system/files/atc19-pang.pdf) | Zanzibar combines relation tuples, namespace policies and causal consistency; its production results depend on Google infrastructure. | Retain OpenFGA composition and HIGHER_CONSISTENCY; do not describe it as Zanzibar zookie or external-consistency equivalence. |
| [Macaroons](https://research.google.com/pubs/archive/41892.pdf) | Macaroons attenuate authority through contextual caveats, all of which must hold. Cryptographic delegation adds issuance/discharge/replay responsibilities. | Keep policies and inspectors narrowing-only; defer a new credential format. |
| [Cedar](https://arxiv.org/html/2403.04651v1) | Cedar provides default denial, forbids overriding permits, deterministic evaluation and formal analysis. Its performance claims concern its compared implementations. | Add explicit argument deny rules that override allows; do not claim a Cedar engine or formal proof. |
| [Efficient and Extensible Policy Mining for Relationship-Based Access Control](https://arxiv.org/html/1903.07530v1) | Feature selection focuses evolutionary ReBAC policy mining on promising attributes. Mining depends on supplied entitlement/object data. | Do not infer production permission grants from observed traffic or model suggestions. |
| [A Decision Tree Learning Approach for Mining Relationship-Based Access Control Policies](https://arxiv.org/html/1909.12095v1) | Decision-tree ReBAC mining balances consistency with source ACLs and structural complexity. Compact policies are not proof that source entitlements are correct. | Keep migration/review explicit and test denied cases, not only equivalent allowed cases. |
| [Greedy and Evolutionary Algorithms for Mining Relationship-Based Access Control Policies](https://arxiv.org/html/1708.04749v1) | The retrieved body is titled Mining Relationship-Based Access Control Policies; greedy/generalization algorithms use an explicit class/object model. | Keep relationship modeling outside routing and preserve the deployed OpenFGA model pin. |
| [Learning Attribute-Based and Relationship-Based Access Control Policies with Unknown Values](https://arxiv.org/html/2008.08444v1) | Unknown-value mining uses three-valued logic and experiments over incomplete entity data. It is an offline policy-learning setting. | Missing tenant, subject or client binding must not be filled in from guesses at request time. |
| [Authentication and authorization in Data Spaces](https://arxiv.org/html/2505.24742v1) | ODRL compilation plus OpenFGA demonstrates a data-space use case; usage control and metadata privacy remain future work. | Keep gateway tool access separate from downstream usage control or record ownership claims. |
| [AutoCedar](https://arxiv.org/html/2607.03656v1) | AutoCedar fixes a reviewed semantic target before verifier-guided policy synthesis. Evaluation corpora and formal encodings bound its claims. | Keep publication review/revision gates; defer autonomous production policy synthesis. |
| [RAISE](https://arxiv.org/html/2609.33796v1) | RAISE trains policy synthesis against symbolic checks; synthetic targets, backbone choices and experimental seeds affect transfer. | Use executable positive/negative boundaries; do not grant live authority based on generated prose. |

## Routing

| Primary paper | Finding and limit | Engineering decision |
|---|---|---|
| [Maglev](https://research.google.com/pubs/archive/44824.pdf) | Maglev balances network flows with consistent hashing and connection tracking. Packet throughput is not MCP call performance. | Retain stable application routing and test eligibility before selection; no throughput parity claim. |
| [Slicer](https://storage.googleapis.com/gweb-research2023-media/pubtools/4405.pdf) | Slicer separates forwarding from a control plane that manages assignments and load. It relies on deployment signals and coordination. | Keep routing behind a narrow plugin interface; do not run a planner in request dispatch. |
| [Beamer](https://www.usenix.org/system/files/conference/nsdi18/nsdi18-olteanu.pdf) | Beamer moves connection-state responsibility to backends to tolerate churn. It assumes transport/backend cooperation. | Do not confuse stateless MCP selection with migration of arbitrary legacy backend sessions. |
| [Consistent Hashing and Random Trees](https://people.csail.mit.edu/karger/Papers/web.pdf) | Consistent hashing minimizes remapping under membership changes, under an explicit caching/network model. | Retain membership-stability tests and avoid attaching authorization authority to affinity choices. |
| [A Fast, Minimal Memory, Consistent Hash Algorithm](https://arxiv.org/pdf/1406.2294v1) | Jump hashing is compact but assumes sequential bucket numbers, limiting arbitrary removals. | Retain weighted rendezvous for named target membership; do not add another strategy solely to increase feature counts. |
| [Dynamo](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf) | Dynamo combines availability-oriented storage techniques and eventual consistency. Some workload details are aggregated. | Do not apply eventual-consistency permission caching to revocation; use shared revisions and explicit failures. |
| [Analyzing Distributed Join-Idle-Queue](https://arxiv.org/html/1606.01833v1) | JIQ fluid-limit analysis identifies high-load variance and assumptions missing from simpler treatments. | Defer queue-aware dispatch until trustworthy shared load signals and measurements exist. |
| [Optimal Rate-Matrix Pruning For Large-Scale Heterogeneous Systems](https://arxiv.org/html/2306.00274v1) | Rate-matrix pruning accounts for task/server heterogeneity with asymptotic assumptions. Faster-server heuristics can reduce stability. | Add explicit priority configuration, but do not call it adaptive or delay-optimal routing. |
| [Join-Idle-Queue with Service Elasticity](https://arxiv.org/html/1803.07689v1) | Elastic JIQ stability is a large-system result; subcritical load alone does not ensure every finite system is stable. | Keep bounded concurrency and avoid claiming scalability from an algorithm name. |
| [Heavy-traffic Delay Optimality in Pull-based Load Balancing Systems](https://arxiv.org/html/1808.06911v1) | Pull-based routing balances communication overhead and delay guarantees; local idle-state information can become stale. | Use configured trusted tenant/role selectors; defer local least-load decisions presented as cluster-wide truth. |

## Reliability

| Primary paper | Finding and limit | Engineering decision |
|---|---|---|
| [Raft](https://www.usenix.org/system/files/conference/atc14/atc14-paper-ongaro.pdf) | Raft separates election, replication and safety in a crash-fault model. A gateway replica count is not itself a consensus system. | Use PostgreSQL for shared configuration; do not implement another consensus layer inside the gateway. |
| [Paxos Made Simple](https://lamport.azurewebsites.net/pubs/paxos-simple.pdf) | Paxos requires intersecting quorums and persistent proposal state; safety and progress are distinct. | Keep transactional revisions and deployment-owned database availability; no distributed exactly-once claim. |
| [The Tail at Scale](https://barroso.org/publications/TheTailAtScale.pdf) | Tail-at-scale techniques distinguish within-request mitigation and longer-term adaptation; hedging can add load. | Add independent connection limits and cumulative upstream deadlines; do not hedge effectful calls. |
| [Viewstamped Replication Revisited](https://www.cs.princeton.edu/courses/archive/fall19/cos418/papers/vr-revisited.pdf) | Viewstamped replication distinguishes stale reads from causally constrained reads and lease assumptions. | Retain fresh shared-revision checks and explicit outage denial rather than stale authorization fallback. |
| [Spanner](https://research.google.com/pubs/archive/39966.pdf) | Spanner combines replication, transactions and clock uncertainty. TrueTime results are not available merely by using SQL. | Keep storage adapters loosely coupled; do not claim global external consistency for the local PostgreSQL deployment. |
| [The Chubby lock service](https://research.google.com/archive/chubby-osdi06.pdf) | Chubby uses coarse-grained locks and fencing to protect against delayed work. Distributed locks require more than familiar local-lock intuition. | Retain bounded leases and no automatic effect replay; defer resource fencing until backend adapters enforce it. |
| [Dapper](https://research.google.com/pubs/archive/36356.pdf) | Dapper prioritizes low overhead, transparency and privacy; it deliberately avoids RPC payload logging. | Keep metadata-only tracing/audit; do not copy payload-capturing vendor defaults. |
| [Large-scale cluster management at Google with Borg](https://research.google.com/pubs/archive/43438.pdf) | Borg handles routine failures through placement, rescheduling and resource policies. Application correctness still requires durable state and failure handling. | Keep Kubernetes lifecycle separate from tool routing; smoke tests are not multi-node disruption certification. |
| [Deconstructing the Tail at Scale Effect Across Network Protocols](https://arxiv.org/pdf/1701.03100v1) | The network tail study compares TCP/UDP/RDMA under a controlled experimental setup. It does not establish a universal benefit from changing protocols. | Keep standards-compliant MCP transports; defer arbitrary RDMA/WebSocket additions without protocol contracts. |
| [KedgeFlow: A Programmable Control Plane for Enterprise AI Agents](https://arxiv.org/html/2610.14810v1) | KedgeFlow binds approved requests to single-use shared claims and retains uncertain outcomes; the reference scope is a single-resource path. | Keep retries disabled for tool effects; stage independent approval, idempotency and reconciliation as a separate durable contract. |
