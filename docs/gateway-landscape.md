# Ten-gateway review — 17 October 2026

This is a curated comparison of ten prominent projects/products, **not a verified worldwide popularity ranking**. Primary documentation and source were inspected after the five-paper-round review. No competitor binary was installed, benchmarked or penetration-tested. Capabilities below are documented claims, not our independent runtime certifications. Unreviewed or undocumented does not mean absent. Product editions, releases and entitlement contracts matter; current documentation can change.

## Capability-to-action matrix

The peer examples refer to the sources in the table above. This is a gap/decision matrix, not a complete Yes/No certification for each vendor.

| Capability | Documented peer examples | Relay result / remaining boundary |
|---|---|---|
| MCP aggregation / virtual endpoint | Docker, ContextForge, Kong, Agent Router, AgentCore | Existing namespaced MCP aggregation retained |
| REST/OpenAPI conversion | KrakenD, Gravitee, ContextForge, Kong, AgentCore | Staged typed adapter; not implemented by ordinary HTTP MCP support |
| gRPC / event integration | ContextForge; Gravitee platform | Staged; avoid pretending all protocols share MCP semantics |
| LLM and A2A governance | Gravitee, Kong entities, ContextForge, agentgateway, Agent Router | Outside current focused MCP data plane |
| Workload provisioning / isolation | Microsoft adapter APIs; Docker execution model | Genuine gap: deploy-owned stdio commands are not isolated server lifecycle management |
| Identity and delegated consent | Gravitee, Kong, agentgateway, AgentCore | JWT/service auth and token exchange retained; interactive consent/SSO/vault lifecycle staged |
| Discovery and call authorization | KrakenD, agentgateway, Agent Router | Existing all-of ACL/role/OpenFGA plus argument checks retained |
| Schema-bound header routing | Microsoft migration; Traefik routing caveat | Added strict annotation validation, upstream mirroring, ingress mismatch rejection and HTTP 400/-32020 tests |
| Stable routing / changing target pools | Traefik HRW; wider gateway routing ecosystems | Added weighted rendezvous strategy and deterministic membership-change tests; no automatic side-effect failover |
| Tenant-safe candidate selection | Relevant to all federating routers | Fixed selection to exclude foreign-tenant targets before weighted/sticky/rendezvous choice |
| Metadata integrity across alternate names | Docker's consistent path-enforcement principle | Fixed physical pins to also constrain aliases, in discovery and execution |
| Fine-grained extension hooks | ContextForge plugins, AgentCore interceptors, gateway policy ecosystems | Added versioned typed API and bounded veto-only pre-call/result inspectors; no untrusted plugin sandbox |
| Efficient authorized discovery | Docker dynamic tooling; AgentCore semantic search | Added bounded literal search and standard pagination; learned/semantic ranking deliberately deferred |
| Aggregate resource limits | Networking and policy ecosystems provide different controls | Added explicit scanned/retained tool and byte budgets, collection deadline and upstream concurrency cap |
| Traffic admission / failure handling | Envoy/Traefik/Kong ecosystems and others | Shared PostgreSQL rate/concurrency/circuit state, local single-instance state, and no blind effect retries |
| Observability / management | Many reviewed projects | Existing UI, history, audit and OTel retained; added discovery controls/search UI; production collector and immutable audit export remain gates |
| Database-backed horizontal operation | ContextForge and control-plane ecosystems; managed AgentCore | Existing PostgreSQL replicas tested; added cross-replica cursors/search/revision tests |
| Signed supply chain | Docker's documented signing scope | Still staged: metadata hashes are not image signatures |
| Independent human authorization | Various governance offerings have different contracts | Still staged: one-use, independently approved, exact-action grants require a full design |
| Operational maturity / support | Commercial platforms and established ecosystems | Not matched by adding code in one release; requires load/chaos/conformance/security maintenance and support operations |

## Decisions made after this comparison

1. Implement weighted rendezvous routing and fix tenant eligibility before selection. Keep routing a replaceable interface and core guards independent of the selected router.
2. Implement modern parameter-header validation/mirroring with explicit strict-spec behavior. The pinned SDK has a known `number`-annotation/conformance discrepancy; Relay follows the specification's permitted primitive types and documents that choice.
3. Complete browser configuration/search and real-store tests for the research additions. Verify collection and search use the same authorization/pin path.
4. Keep lifecycle, signed admission, enterprise consent, API conversion, semantic/graph ranking and independent approvals as explicit backlog designs. Shipping partial imitations would create misleading security and compatibility claims.

These changes strengthen a focused, extensible MCP gateway. **Neither the reviewed documentation nor our tests establish that no other gateway offers these features.** No universal performance, completeness or security ranking is supported. Reproducible equivalent-policy benchmarks and installed-version compatibility tests are required before comparative performance claims.
