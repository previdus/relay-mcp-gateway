# Security boundaries and remaining workSee [authentication, ReBAC migration and reliability boundaries](component-hardening.md). DPoP-bound JWT and introspected OAuth tokens are supported when explicitly enabled with a client-visible HTTPS origin and replay store; PostgreSQL is required for replay protection shared across replicas. RFC 8705 certificate-bound OAuth tokens remain unsupported; certificate-only mTLS identity is supported when the gateway terminates TLS directly. Introspection is fresh and bounded, while locally verified JWT revocation still depends on issuer expiry/key policy or a separate deployment-owned revocation mechanism. OpenFGA tuple-v2 requires a deliberate migration. Side-effect retries remain disabled.

| Threat | Implemented control | Remaining boundary |
|---|---|---|
| Unauthorized tool calls | Per-request identity and all-of permissions; same checks filter discovery | Tenant-scoped upstreams and verified JWT mapping; global administration remains privileged || Custom router target substitution | Core binds a physical public name to the same upstream/tool; aliases must resolve within their enabled, selector-eligible configured target pool; an optional remote router receives only that candidate pool | In-process plugins remain trusted code; remote routing adds a dependency and receives identity metadata, so restrict its service identity/network || Remote tool inspection | Optional pre-call and post-call service can veto, with exact endpoint credential binding and bounded payload/deadline | Arguments and results are intentionally sent to that deployment-owned processor; classify the data, approve its region/retention, and note post-call denial cannot undo an action |
| Scope escalation through aliases | Aliases require exact grants; namespace wildcards only match namespaced tools | Compatible backend contracts are operator-managed |
| Cross-service token reuse | Inbound audience checks in JWT mode; separate outbound credentials | Client credentials and token exchange supported; interactive authorization and refresh-token storage remain open |
| Policy outages | Authorizer errors deny access; unavailable shared state rejects new requests | Admin availability / disaster recovery untested |
| Revoked relationships | Pinned OpenFGA model and higher-consistency checks without gateway decision caching | In-flight calls retain their starting authorization; they are not retroactively undone |
| SSRF / credential exfiltration | Strict mode checks and pins DNS for MCP upstreams, PostgreSQL, OAuth token/introspection, JWKS, OPA/OpenFGA, configured remote extensions, and the OTLP HTTP trace exporter; strict PostgreSQL mode requires CA and hostname-verified TLS | Strict mode is opt-in for compatibility; arbitrary plugin egress still needs network policy and production monitoring |
| Browser attacks | Host/origin checks, separate admin key, CSP, no dynamic HTML interpolation, no stored browser key | Admin SSO, CSRF penetration testing, security headers at ingress still need review |
| Malformed / excessive input | JSON request cap, tool argument schema checks, node/depth limits | Regex/schema execution needs CPU isolation before treating upstream schemas as untrusted |
| Excessive upstream output | Declared and streamed response byte caps | Binary/media handling compatibility needs broader tests |
| Duplicate side effects | No automatic tool-call retries | Caller must handle ambiguous timeout outcomes and application idempotency |
| Replica contention / crashes | PostgreSQL atomic revisions and expiring concurrency leases | Rate quotas, production load tests, network partitions and clock/failure scenarios pending |
| Audit loss | Persisted metadata without tool arguments/results or credential values | Atomic configuration/audit and fail-closed admission; immutable retention remains open |

Administration is a trusted, powerful role: it can change upstream destinations and permission policies. Restrict management networking and secret-reference choices with deployment controls. Runtime plugins are trusted code installed with the application, not untrusted uploads.

Use TLS, managed secrets, verified database TLS, restricted database credentials, network policy, backups, retention, dependency scanning, and reviewed releases in production. These deployment properties are not automatically supplied by this source package. See the coverage and validation records before exposing the gateway.
