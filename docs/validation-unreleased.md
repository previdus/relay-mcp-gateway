# Unreleased workspace validation

Validation through 19 October 2026 on Windows with Node.js 22.14.0. The latest TypeScript check/build and 196-test core suite pass; the suite covers the published `@modelcontextprotocol/ext-tasks` V2 requester adapter and a mixed legacy/modern demo alias, including completion decoding, opaque `Mcp-Name` translation, and consistent routed tool contracts. Regressions also prove unsafe PostgreSQL addresses are denied before connection, PostgreSQL SSLRequest precedes startup credentials, exact-bound live PostgreSQL queries verify CA and hostname, application authorizers cannot override OPA denial or widen client grants, strict deployment egress blocks plugins from disallowed loopback endpoints, and conflicting application authentication/approval plugins fail readiness. The real PostgreSQL/OpenFGA/OPA service suite passed 13/13, including untrusted-CA and hostname-mismatch rejection. All 10 Chromium workflows passed on the previous final runtime source revision. The hardened v0.12.0 container passed acceptance; this turn reran the disposable container acceptance against Docker Desktop and verified discovery, tool calls, policy revocation, audit and read-only non-root execution. Docker Desktop already had a healthy Linux engine; the earlier shell failure was the workspace sandbox denying access to its API. Read-only checks through the approved host path confirmed Docker 29.8.2 and two Ready Kubernetes 1.36.1 nodes. The local in-process demo is running at `http://127.0.0.1:3000/admin/`; its generated administrator and service keys are temporary and rotate when the process restarts. The full Kubernetes acceptance passed on the source checkpoint before the runtime security-plugin composition changes and has not been rerun since. Its script requires the dedicated `kind-relay-validation` cluster; the currently healthy Docker Desktop cluster is intentionally not substituted because it is the user's local cluster. The Docker/WSL issue had previously been traced to kubelet rejecting cgroup v1; WSL was updated to 3.0.3 (kernel 6.18.54), cgroup v2 was enabled, and Docker Desktop's two-node cluster starts with both nodes Ready. Earlier release results below apply only to their named source checkpoints and do not revise or replace the v0.12.0 release image record.
